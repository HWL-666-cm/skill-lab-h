## 2. 四个问题逐项验证

### 2.1 术语稳 —— 候选术语 + 代码级强制回填（主攻）

BERT 抽取 **80 个候选术语**（缩略词 + 专有短语 + 高频 n-gram），示例：

```
acronym: BERT×99, CLS×28, GPT×27, GLUE×18, NSP×16, MNLI×14, MLM×13
phrase : OpenAI GPT×18, BERT BASE×17, BERT LARGE×14
ngram  : natural language×17, learning rate×11, batch size×9, question answering×8
```

**术语表"真正执行"的证据（确定性校验器实测）**：给定术语表 `attention→注意力（禁用：关注、注意机制）`，对漂移译文逐段校验：

| 输入译文 | 校验器判定 | 动作 |
|-|-|-|
| `BERT 使用注意力并报告…`（正确） | `accepted` | 通过 |
| `BERT 使用注意机制并报告…`（漂移） | `needs_review`：`forbidden_hits=[注意机制]`、`missing_terms=[attention→注意力]`、`placeholder_issues=[{{P_1}}缺失]` | **强制回填** `注意机制→注意力` |

即：模型译漂了，代码把它改回来——这是"术语表被真正执行"与"基础 Agent 只是把术语表粘进提示词"的本质区别。

### 2.2 段落全 —— 多栏阅读顺序 + 行→段落聚合

| 文档 | 段落数 | 覆盖页 | 公式段（不译） |
|-|-:|-:|-:|
| BERT | 329 | 1–16（全覆盖） | 32 |
| Decision Transformer | 277 | 1–21（全覆盖） | — |

复用阅读01 已跑通的**竖直栏缝检测**（BERT 双栏页 `column_switches=1`，先左后右、零串栏），再按行距+首行缩进把"行"聚成"段"，每段唯一 `id` + 页码/栏位/章节定位。

**段落数与阅读01 报告差异说明**：阅读01 报告的 `paragraph_count`（BERT 1323 / DT 830）实为**行数**（extractor 把每个视觉行记为一个 paragraph）；本题 329 / 277 是 `group_lines_to_paragraphs` 把同页同栏的连续行**聚合成真实段落**后的**段数**。两者是"行→段"聚合关系，非过滤：已实测 BERT 1323 行全部落入 329 段、0 行丢失、字符数守恒（48247→48247）。已知边角：页 1 标题/摘要块的通栏↔栏位归属偶尔使前几段顺序微调，Agent 依渲染页图校正。

### 2.3 关系准 —— 占位符保护

Decision Transformer 全文 **130 个占位符**，覆盖 54 段；36 个含数字引用的段**全部被保护（0 遗漏）**。实测示例：

```
source   : …arXiv preprint arXiv:1910.00177, 2019. [25]
protected: …arXiv preprint {{P_1}}, 2019. {{P_0}}
map      : {{P_0}}="[25]", {{P_1}}="arXiv:1910.00177"
```

另验证：`91.0%`→`{{P_1}}`、`110M`→`{{P_2}}`、`(1)`（公式编号）→占位符、`0.1 m/s`（复合单位，按首个单位保护）。

### 2.4 可核验 —— 段落级双语定位

每段输出 `{id, page, column, section, source, protected, protection_map}`，`id` 与 translation_job 段号一一对应，评审可按 `id/page` 指回原文核对。

## 5. 诚实标注的不足

1. **作者-年份式行内引用**：BERT 论文的 `(Zhu et al., 2015)` 在提取阶段丢失（正文只保留了参考文献全名），需对照渲染页图补回；正则已支持括号内作者-年份形式，但该语料未复现。
2. **复合单位**：`m/s` 按首个单位 `m` 保护，剩余 `/s` 由翻译指令兜底。
3. **译文语言质量**：流畅度取决于运行时 DeepSeek 模型，本 Skill 只做"约束与核验"，不能替代模型本身的能力（本报告不虚构译文评分）。

## 6. 结论

本 Skill 已形成"确定性抽取/分段/保护/校验 + 模型翻译"的最小闭环，四个问题各有**可执行、可核验**的解决方案，主攻方向（术语表代码级强制执行）有明确机制证据。下一步：建 GitHub 公开仓库 → 更新终版 → `submit --dry-run` 预检 →（确认后）正式提交。
