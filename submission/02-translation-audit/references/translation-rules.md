# 翻译可靠性规则（术语 / 数字 / 否定 / 限定）

本文件是判断"什么算保真、什么算走样"的口径。审计脚本只覆盖能机器判定的部分，
其余靠 Agent 按本文件自检。

## 一、优先级（冲突时按此顺序取舍）

**原文含义与证据边界 > 术语一致 > 结构与符号 > 自然通顺 > 文风偏好**

含义与术语冲突时以含义为准，但要单列说明；绝不能为了通顺丢掉限定或否定。

## 二、术语

1. **一概念一译名**：同一 `concept_id` 全篇只用锁定译名，不得同义替换。
   中文没有词形变化，所以"换个说法"就等于换了术语，属于漂移。
2. **同形异义要分概念**：同一个英文词在不同语境是不同概念时，分别建 concept，
   不做全局字符串替换（例：`model` 在"数值模式"与"模型"语境下要分开）。
3. **缩写**：首次出现写"中文（ABBR）"，之后可用 ABBR；
   ABBR 必须与原文一致，不得自造缩写。
4. **不译项**：文献题名、作者名、期刊名、软件名、数据集代号通常保留原文。

## 三、数字与单位

| 情形 | 处理 |
|---|---|
| `+2 h`、`+12 d` 这类带正负号与单位的量 | 数字与单位**原样保留**，不要改写成"两小时""十二天" |
| 百分数 `89.7 %` | 保留数值与 `%` |
| 分辨率 `0.1°×0.1°`、`9 km×9 km` | 保留数值与符号 |
| 阈值 `< 1200 m`、`≥ 60 m` | 保留不等号方向（左闭右开等方向写反是硬错） |
| 中文语序需要调整时 | 数字与单位可换位置，但值不能变、单位不能丢 |

**为什么强调**：数字写成中文后，机器无法核验、人也容易漏看，
实测这是基础 Agent 最常犯的锚点丢失（B 版 4 个时效全部丢失）。

## 四、否定与限定

必须保留的否定：`not / no / never / without / none / neither / nor / cannot / unable / unresolved`。

必须保留的限定（**不得升级为确定**）：

| 原文 | 可译 | 不可译 |
|---|---|---|
| may / might | 可能 | 会、必将 |
| suggest / indicate | 提示、表明 | 证明、证实 |
| likely / probably | 很可能 | 一定 |
| in this study / under the tested conditions | 本研究、在所测条件下 | 删除限定直接下结论 |
| preliminary / to our knowledge | 初步、据我们所知 | 删除 |

**禁止把否定与限定移出它约束的范围**：`not all models improve`（不是所有模式都改进）
不能译成"所有模式都没有改进"。

## 五、引用与公式

| 形式 | 保留方式 |
|---|---|
| `(Gultepe et al., 2007)` | `（Gultepe et al., 2007）` 或 `（Gultepe 等，2007）`，**年份必须留** |
| `Kneringer et al. (2019)` | 同上，年份留 |
| `[3]`、`[3–7]` | 方括号编号留 |
| `Eq. (1)`、`Fig. 2`、`Table 1` | 编号留，`Fig.` 可译"图"但编号不能丢 |
| 公式本体 | 原样保留，不改写；公式内可译文字单列为受控修订 |

## 六、原文有问题时

- 原文疑似笔误、单位写错、逻辑跳跃：**按原文译**，在 `uncertainties` 里单列"原文疑似问题"。
- 不得"顺手纠正"。翻译的职责是忠实传达，不是替作者改稿；改稿要单独授权。

## 七、译不准时

- 用 `【待核】` 就地标注，并写进 `uncertainties`（含 pid 与原因）。
- 不允许用模糊表述掩盖（如把不确定的术语译成一个笼统的上位词还不标注）。

## 八、中文表达（不牺牲保真）

- 拆长句、调整语序以消除翻译腔，但**不改变命题与证据绑定**。
- 用准确的学术动词，不用空泛词（"进行了分析"可改"分析了"）。
- 不为了"高级"而加原文没有的程度词（显著、大幅、首次、端到端）。
