## 作品做了什么

把一组论文转成**每条边都站得住**的文献知识图谱。四个把关点对应题目四问：

| 题目四问 | 落地方式 |
|---|---|
| 抽得准 | 节点名必须能在原文里找到（`label_in_source` 硬检查）；不给"常识补全"留口子 |
| 连得对 | 13 类谓词各带 domain/range，签名不合直接失败；方向按谓词分主动/被动两套触发词判定；证据强度按"自述 / 方法 / 综述 / 转述 / 假设"六档，第一人称覆盖引用标记 |
| 对得齐 | 三层身份决策：同篇别名→合并并记依据；跨篇"产品级"（缩写/版本号/显式标识符）→合并并标 `identity_scope: product`；其余→写进 `candidate_alignments` 且 `decision: not_merged` |
| 查得到、回得去 | 每个节点/边绑 `source_id + paragraph_id + 逐字引文`；**禁止 page 字段**（本包无 PDF 页码，出现即失败）；5 类查询，答不出就返回 `insufficient_evidence` |

三步流程：`prepare`（切段切句、提候选，不做判断）→ Harness 按 `SKILL.md` 写 `draft.json` → `finish`（对齐、组装、查询、门禁、导出 7 个文件）。

无模型时 `--stage auto` 兜底：纯规则草稿，召回低但一定跑得动，产出明确标注是规则候选。

## 已知不足（如实）

1. **召回偏低**：21 条边只覆盖 124 段中的 11 段。Skill 的定位是"门禁 + 约束"而非抽取器，`auto` 模式是低召回兜底，真正的召回靠 Harness 按 `SKILL.md` 写草稿。
2. **13 类关系用到 11 类**：`CONTRADICTS` 为 0，因为两篇主题不重叠、没有正面对撞的结论。没有证据就不连边，不造假冲突。
3. **`PERSON` 实体为 0**：两篇正文里研究者只出现在作者列表与引用标记中，不作为科研对象被讨论。
4. **段落 id 大量生成**：40 段中 27 段、84 段中 70 段的出版方 XML 无 id 属性，Skill 自建 `p001…` 并标 `id_source: generated`，在 `uncertainty` 里写明。
5. **A/B 不是平台跑分**：A 组是本人按"不带规则"方式写的对照稿，能证明校验器有区分度，不能证明提升倍数。
