# 锚点格式与核验规则

## 一、锚点的三层粒度（按可核验性排序）

| 粒度 | 写法 | 什么时候用 | 脚本判定 |
|---|---|---|---|
| 强 | `page` + `section` + `quote` + `value` 含数值 | 正常文本页 | `ok`（quote 能找到 + 数值在页上） |
| 中 | `page` + `section`，quote 空 | 乱码页/图片页/公式页 | `weak`（页面存在，但无法逐字核验） |
| 弱 | 只有 `section` | 实在定位不到页 | `weak` + `missing_page`，必须进 limitations |

**设计动机**：03 题评分点名"锚点粒度与可核验性匹配"。乱码页硬写 quote 反而是编造；允许降级到页级、并明确标注，比假装精确更诚实，也更符合"找得回"。

## 二、核验脚本怎么判（anchor_audit.py）

按 claim 逐条做五件事，全部是本地计算、不消耗模型额度：

1. **页码存在性**：`page` 缺失 → `missing_page`；页码找不到 → `page_not_found`。
2. **页码映射**：`page_map` 把印刷页码映射到 PDF 页序，贯穿所有核验步骤（quote、数值、章节）。
3. **quote 回原文**：NFKC 规范化 + 去空白后子串匹配；本页找不到允许 ±1 页容错（处理 PDF 分页边界），再找不到 → `quote_not_found`。
4. **数值回原文**：`value` 里的数字（含全角）逐个在该页附近找；找不到 → `numbers_not_on_page`。无页码时退化为全篇扫描 → `numbers_not_in_document`。
5. **章节一致性**：`section` 在目录中存在但页码差 >1 → warning `section_page_mismatch`（不降级 verdict，只提醒）。

verdict 判定：
- `ok` — 无 flag
- `weak` — 缺页码/粒度不足，但没有内容性错误
- `mismatch` — quote 找不到 或 数值不在页上（内容性错误，必须回改）

## 三、已知边界（如实写进文档，不藏）

- **全篇数值扫描的局限**：若 claim 写错成论文里别处出现过的数字（例如把 p7 的 0.46 写成 p6 的结论），无页码时全篇扫描找不到错；只有补了页码才能靠 `numbers_not_on_page` 抓出。所以流程上要求"先补页码再核验数值"。
- **quote 的 ±1 页容错**：跨页句子可能被切到相邻页，因此允许相邻页命中；这也意味着页码写偏 1 页不会被抓。对精度要求高的场景应人工抽查页码。
- **图片/表格数字**：PDF 文本层读不出图片里的数字，脚本不会从页面图像 OCR（平台有 `pdf-render-tool`/`ocr-tool` 时可人工补）。这类数字必须标注"从页面图像转录"，不能当文本抽取。
