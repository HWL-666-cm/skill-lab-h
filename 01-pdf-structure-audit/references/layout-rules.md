# 版式判据与阈值：为什么这么定

这份文档只讲一件事：**每条判据是用来挡住哪种真实错误的，阈值是从哪次实测里定出来的。**
所有数字都来自本地对两篇公开论文的实际测量（Dietz et al. 2019, ASCMO, 14 页双栏；
Chen et al. 2024, Scientific Reports, 12 页单栏）以及 `tests/` 下的合成件。题录见 `benchmark.md`。

> 通用原则：**宁可少认一项，也不编一项。** 判据不成立时输出"检测到但未结构化"，
> 而不是给一个看起来完整的错结构。

---

## 1 分栏（layout.py）

### 1.1 只用"窄正文行"当样本

**要挡的错误**：摘要、跨栏表、通栏标题会跨过栏缝，把它们算进样本会得出"左栏的行越过了右栏左边缘"，
于是一整页被判成单栏，正文逐行左右交错读出。

- 实测：Dietz 第 1 页摘要通栏，整页被误判 1 栏；第 4 页有整幅通栏表，同样误判。
- 判据：`width(行) < 0.62 × 正文区宽` 且 `len(文本) ≥ 25` 才作为样本。
- 为什么还要 `len ≥ 25`：表格单元格（`lvp`、`(m)`）又窄又短，会把栏缝估算带偏
  （Dietz 第 4 页因此把栏缝算到 x=245，真实是 297，差 50pt）。

### 1.2 交叉率阈值 0.45

**要挡的错误**：把单栏页误判成多栏。

- 判据：对每一道候选栏缝，取"左于该缝的所有行"，若其中 **> 45%** 的行右边缘越过右栏左边缘，
  判为单栏。
- 为什么是 45% 而不是 20%：通栏表/摘要会把该比例抬高（Dietz 第 4 页硬卡 20% 就退回单栏）；
  而真正的单栏页几乎 **全部** 行都跨过伪栏缝（实测 70% 以上），45% 仍能判回单栏。

### 1.3 栏缝位置用中位数，且只用"紧邻左栏"的行

**要挡的错误 ①**：取左栏行右边缘的最大值会把栏缝算成负数（通栏表的描述列会伸进栏缝：
Dietz 第 4 页描述列 x1=309.8，右栏起点 307.3）→ 改用中位数。

**要挡的错误 ②**（合成件 three_column 实测）：三栏页算第二道栏缝时，若把"所有更左的行"
都算进中位数，中位数会被第一栏较短的右边缘拉低，栏缝落到第二栏中间——
真栏缝是 379→392，被算成 317.8→392.9，于是第二栏的行被当成"通栏行"各自成带，
三栏文字交错读成一团（63 段垃圾 → 修正后 19 段、锚点 0.68 → 1.00）。

- 判据：`adjacent = [行 for 行 in 样本 if merged[i]-2 ≤ x0 < merged[i+1]-2]`，
  用它算中位数；不足 4 行时才退到"所有更左的行"。
- 表间距至少 6pt 才认这道缝（`right_start - left_med ≥ 6`）。

### 1.4 通栏行作分区边界（reading order）

**要挡的错误**：标题在左栏之上、摘要通栏、下面是两栏——如果只按"先左栏后右栏"排，
通栏摘要会被排到左栏之后，标题与正文断开。

- 判据：行的 bbox 跨过任一 `split`（`x0 < s < x1 - 2`）即"通栏行"，它把页面切成若干带；
  带内再按 `栏 → y` 排序。
- 效果：Dietz 14 页的**回跳**（读到右栏后又跳回左栏且上移）从默认顺序的 101 次降到 0。

### 1.5 阅读顺序指标只数"回跳"

**要挡的错误**：用"横向跳转"当指标会把正常的换栏（右栏读完回到左栏下一段）也算成错，
Dietz 上会得出 0.46 的错误结论。

- 判据：`dx < -150 且 dy < -20` 才算一次回跳（既大幅左移、又上移，这是串栏交错的指纹）。

### 1.6 行内大间隙切段（pdfcore.page_lines）

**要挡的错误**：PyMuPDF 会按基线把同一 block 内的 span 合成一行。如果 PDF 把相邻栏的文字
放进同一个文本块（某些生成器会），左栏行尾会和右栏行首直接拼成一句。

- 判据：相邻 span 的间隙 `> max(6.0, 1.0 × 字号)` 就切开。
- 为什么阈值是"1 倍字号"：正文词间距通常 0.2–0.4 倍字号，栏缝普遍 ≥ 1 倍字号。
- 实测：两篇真实论文上 **一次都没触发**（说明对正常 PDF 零副作用）；
  合成三栏件上正是靠它把"三栏拼一行"拆开。

## 2 页眉页脚（structure.detect_running）

**要挡的错误**：每页顶部/底部的刊名、作者名、页码混进正文，导致每页都插进一行假正文。

- 判据：① 位于页面顶/底带（`y1 ≤ top+6` 或 `y0 ≥ bottom-6`，带边界取页高 10%）；
  ② 文本"数字归一"（`\d+ → #`）后跨页重复，且出现次数 `≥ max(2, 0.4 × 页数)`；
  ③ 页数 ≥ 3；
  ④ **字号 < 正文 × 1.05**。
- 为什么加 ④（合成件 single_column 实测）：连续两页的章节标题恰好满足"同位置、数字归一后相同"
  （`2 Method` 与 `3 Method` 都是 `# method`），被判成页眉后直接从目录里消失。
  页眉是版式元素（字号不大于正文），标题是内容元素（字号大于正文），这条能分开两者。
- 只排除"字号明显更大"，**不排除"加粗但同字号"**：Scientific Reports 每页顶部那个加粗的
  `OPEN` 标就是加粗同字号，放行后每页混进正文（Chen 实测多出 11 段）。
- 页码单独抠出：`trailing digits` 记入 `page_label`，`role=page_number`。
- **隔离 ≠ 删除**：这些段落仍留在 `pages[].paras` 里，只是不参与正文流，可随时回查。

## 3 章节标题（structure）

标题必须同时满足多条，因为单条判据都有反例：

| 判据 | 挡住的错误 |
|---|---|
| 编号后要求以字母/汉字开头 | 公式碎片 `0 ,θ*` 被当章节 |
| 编号后必须 `. : ： \| 、` 或行尾 | 正文引用"Figure 3 shows…"被当题注 |
| 与栏左边缘对齐（≤ 8pt） | 算法步骤 `3. Fit the gradient vector…` 被当章节 |
| 含 `=` 则否决 | 行内公式 `3. x = f(y)` 被当章节 |
| 编号部分不含 `. ` | 编号后紧跟句子（`1. Introduction of the…` 是正文列表项） |
| 字号 ≥ 正文 1.02 倍 / 加粗 / 带点号编号，三者至少一条 | 纯编号行（`3`）被当标题 |
| 粗体短行再加"≤ 10 词 + 无 `. `" | 粗体引导句（`Author contributions. The concept…`）整批进目录 |
| 首页先划"前言区"（标题→摘要/首个编号标题之间） | 作者行、Correspondence 被当章节 |
| 纯编号标题需与栏左对齐且下一行不是列表项 | `1.` 这类编号被误认 |
| 标题整块合并同字号连续行 | 折成 2–3 行的标题只取到最后一行（Dietz 实测只拿到 "horizons using tree-based boosting models"） |

## 4 表格（tables.py）

### 4.1 为什么不用 `find_tables` 一把梭

同一篇论文（Dietz 2019，PyMuPDF 1.28.2）实测：

- `find_tables(strategy="lines")`：全篇**只找到 1 个 2×2 小表**，正文里明确的 Table 1/2 一个都没认出来
  （有线策略依赖闭合边框，缺竖线就失效）。
- `find_tables(strategy="text")`：第 4 页给出 **77 行 × 10 列**，第 5 页 73×6，第 6 页 63×6——
  把正文段落也吞进表格。

所以走"题注定位区域 → 区域内按词坐标重建网格 → 一致性校验"三步。

### 4.2 区域定位

| 判据 | 为什么 |
|---|---|
| 题注定位，题注优先取"表体在上/在下一页"的多种候选 | 表题在上最常见；Chen 2024 的 Table 2 题注在页底、表体在下一页顶部，只在同页找会一张都测不到 |
| 用横线（顶线→底线）定上下界 | 按"题注下方第一个正文段"会把表头当正文，区域被压成 10pt 高（Dietz 第 4 页实测） |
| 横线跨度收紧左右边界（窄于请求区域 88% 才收） | 见下 |
| 双栏页里默认只取"题注所在栏" | 用整页宽度会把隔壁栏正文当表格列（Dietz 第 3 页 Table 1 因此多出第 7 列） |
| 窄区域与整页宽度各试一次，取"通过校验且非空单元格更多"者 | 跨栏大表（Dietz Table 2 左右两块）在窄区域里只抓到一半 |

**横线收紧的实测理由**：Dietz 第 3 页 Table 1 的横线只跨左栏（44.5→290），
但区域被放宽到整页（44.5→550.2），右栏正文因此被切成第 7 列，内容是
`error remain unchanged with forecast horizon…`，还连带多出两行。
**为什么不能靠"低填充率就裁列"**：那一列在 6 行里有 4 行都有字（右栏正文行正好和表格行对齐），
填充率 0.67，任何填充率规则都判不出来。横线是表格自己画的，它的起止点就是物理边界。

### 4.3 网格重建

- 行：按 y 中心聚类，容差 `max(3.0, 0.62 × 中位行高)`——上标不会自成一行，紧密排布的行也不会合并。
- 行内词序：先按**纵向重叠**聚行再按 x 排。**为什么**：上标（`(m w.e.)*` 的 `*`、`x²` 的 `2`）
  纵向比同行文字高，按 y 排会把上标提到行首——实测把 `(m w.e.)∗` 排成 `w.e.)∗ (m`。
- 列：把词覆盖的 x 区间涂到 1pt 网格，连续空白 ≥ 7pt 即列缝（`COL_GAP_MIN`）。
  没有竖线时反而更干净；每个词按左上角归入唯一单元格，不会把词劈开。
- 裁边缘列：仅裁"填充率 ≤ 0.5 且像正文"的最左/最右列，且保留至少 2 列。
- 折行合并：与上一行**字框重叠**（`gap < 1.0`）且整行只有一格有字的行，并回上一行。
  **为什么用"重叠"而不是"行距小"**：正常数据行之间总有 2pt 上下空白，而折行两行的字框 gap 是负的
  （Chen 第 9 页实测 −1.9pt vs 正常 +2.2pt）。
- 兜底扫描（无题注）：连续 ≥ 3 行、每行 ≥ 3 个对齐单元格、签名一致。
  **为什么要求 ≥ 3 列**：双栏正文每行天然能被切成 2 段，只要 2 列就把整页正文误判成表格。

### 4.4 校验（敢不敢认）

| 阈值 | 值 | 挡住的错误 |
|---|---|---|
| 行数 × 列数 | ≥ 2 × 2 | 碎片 |
| 非空率 | ≥ 0.35 | 切片区域 |
| 平均单元格字数 | ≤ 60 | 正文被当单元格 |
| 单格 > 18 词的占比 | ≤ 30% | 长句被切碎成"列" |
| **≥ 6 词的格子占比** | **≤ 45%** | 多栏正文被当成表格（合成件 three_column：20×3 假表，锚点 0.68） |
| 区域高度 / 页高 | ≤ 0.75 | 区域吞掉整页 |

「≥ 6 词占比」这条是补充上去的：真表格里长格子只占少数（Dietz Table 2 有一列 Description，
6–7 词的格子只占 7%），而"每行被切成几段"的正文几乎每格都是 6–9 词的长句碎片。

### 4.5 跨页续表合并

仅当 **同一张表** 满足：列数相同 + 表头高度相似（或题注带 `continued`）+ 位于下一页顶部（`y < 0.3 × 页高`）
+ 页码连续。合并后保留 `pages` 区间，不丢第二页的表头信息。

## 5 公式（formulas.py）

| 判据 | 挡住的错误 |
|---|---|
| 数学字体（CM*/Symbol/STIX…）或数学字形（希腊字母、`∑∫∂∇≈≤` …） | 普通正文被当公式 |
| 右缘独立括号编号 `(3)` 作锚点，同列向上下 ±32pt 扩展合并碎片 | 公式被拆成多行后只取到一行 |
| 碎片密度阈值 `≥ 0.12`（或长度 ≤ 8 的短符号） | 正文行被拉进公式 |
| 排除表格 bbox 内的行 | 表格单位（`(m)`、`(◦C)`）被当公式 |
| 排除散文（停用词占比高）与列表项 | 算法步骤被当公式 |
| 上下标：字号 < 0.92 倍 + 基线偏移 | `x2` 应还原成 `x^{2}`；输出 `raw` 与 `scripted` 两版，逐字保真优先 |
| 只找到编号、找不到主体 → `status=number_only` | 不能假装公式提取成功 |

## 6 锚点回验（anchors.py）

**要挡的错误**：整条流水线都在"推断"，如果没有回抽核验，"可核验"就只是自述。

- 做法：拿每个单元的 `bbox` 去原 PDF 取词，把单元的 token 集合与回抽 token 集合比对，
  算覆盖率；按类型取阈值：正文/标题 0.85，表单元格 0.70，公式 0.50（公式的字符常被打散）。
- `pass_rate = passed / total`；**总数为 0 时写 `null` 而不是 0.0**——
  0.0 会被读成"全都核验失败"，事实是"没有东西可核验"（整篇扫描件就是这种情况）。
- 失败的单元进 `anchors.json.failures`，带 `coverage`、阈值、原因；**不静默修补**。
- 实测：Dietz 0.9929、Chen 0.9951、合成单/双/三栏均 1.00。
