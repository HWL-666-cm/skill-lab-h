# 来源分级与冲突规则

## 为什么分级

同是"学习率 1e-4"，写在 `config.yaml` 里和写在论文正文里，证据力完全不同。

- 配置文件的 `1e-4` 是**运行本身**：程序读这个键，用它更新参数。
- 论文里的 `1e-4` 是**对运行的描述**：只证明"作者这么写"，不证明"程序这么跑"。

不分级就会出现两种错误：把论文里的值当成事实（于是代码里真正的值被当作"冲突"），或者把配置里的值当成唯一定论（于是论文明显写错了也查不出来）。

| 等级 | 来源 | 权重 | 能否定冲突 | 典型误用 |
|---|---|---|---|---|
| `author_confirmed` | 作者书面确认 | 6 | 能 | 没有记录是谁、何时确认的 |
| `config` | 配置文件 | 5 | 能 | 把注释里的示例值当成键值 |
| `log` | 运行日志 | 4 | 能 | 把不同 epoch 的学习率调度当成多个值 |
| `code` | 代码默认值 | 3 | 能 | 把断言、比较、表达式当成赋值 |
| `manuscript` | 论文、README、表格 | 2 | 否 | 把"我们用了"当成"跑的就是" |
| `other` | 其他文本 | 1 | 否 | — |
| `none` | 无来源 | 0 | 否 | — |

## 冲突判定（四条规则，按顺序）

**规则一：同一参数名 + 同一作用域 + 不同值 = 冲突。** 两值并列保留，不取平均、不取最新。

**规则二：同一文件里的不同作用域不算冲突。** 一个配置同时写 `train.batch_size: 32` 与 `infer.batch_size: 64`，作者已经用分节回答了问题；一张结果表的每一行也是一个独立配置。把这两类判成矛盾，会让正确的手稿被阻断。

**规则三：跨文件比同一参数名——这正是要抓的东西。** 配置写 `learning_rate: 1e-4`、日志写 `lr: 1e-3`，如果按作用域字面比（配置的作用域是分节名 `train`，日志的作用域是行的位置 `log/epoch1`），这条永远撞不上。所以冲突比较跨越作用域，只在参数名一级进行。

**规则四：散文与硬来源之间是单向的。** 硬来源的每个值都必须出现在散文里；散文多提到的实例不算矛盾。理由：一份 README 常常同时记录多次运行（快速上手用 `imgsz=640`，Cityscapes 基准用 `imgsz=2048`）。要求两侧集合完全相等，会把正确的 README 判成阻断级冲突——这是在真实材料上踩出来的，不是假设。

## 严重度

| 情形 | 严重度 | 为什么 |
|---|---|---|
| 两个硬来源互相矛盾 | 阻断 | 运行自相矛盾，任何稿件都不可能同时正确 |
| 硬来源与散文不一致 | 重要 | 散文可能在描述另一次实验，需作者一句话澄清 |
| 散文内部多实例 | 重要（追问） | 散文无法说明哪个值属于哪个模型 |
| 仅散文有值（无硬来源） | 重要 | 无法与真实运行核对，复现最可能在这里失败 |

## 状态词

| 状态 | 含义 |
|---|---|
| `confirmed` | 有硬来源，且无冲突 |
| `manuscript_only` | 只有散文，没有配置/日志/代码 |
| `conflicting` | 不同文件对同一参数给出不同值 |
| `prose_multi_value` | 散文描述了多个实例，需作者指出哪个适用 |
| `weak_source` | 来源等级低于散文，无法用于核对 |
