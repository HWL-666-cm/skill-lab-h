# 字段字典：论文卡片与 claim

## 一、paper_card 的七个字段（论文卡片，支持并排比较）

| 字段 | 写什么 | 不写什么 | 锚点要求 |
|---|---|---|---|
| `title` | 论文标题，按原文 | 不要按 DOI 或文件名猜 | 可不填锚点（首页可见） |
| `research_question` | 作者要回答的问题，一句话 | 不要写成"本文研究了……的意义"这类空话 | 对应引言末尾或摘要 |
| `data` | 数据来源、时段、样本量、粒度 | 不要漏掉时间窗——离开它数字不可比 | 对应"资料/Data"章节 |
| `method` | 方法名 + 关键设置（模型、参数、阈值） | 不要只写方法名不写条件 | 对应"方法/Method"章节 |
| `main_findings` | 主要结果，带原文数值 | 不要写"效果较好"这类无数值结论 | 每条结果单独成 claim |
| `limitations` | 作者自陈的局限 + 你发现的边界 | 不要把自己的猜测写成作者观点 | 对应讨论/局限章节，没有则进 uncertainties |
| `condition_for_conclusion` | 结论成立的前提（时段、样本、判据、分组） | 不要省——这是"留得住"的核心 | 与 finding 同页或方法页 |

## 二、claim 的 field 取值（六类，用于检索与比较）

- `research_question` — 研究问题
- `data` — 数据与样本
- `method` — 方法与条件
- `finding` — 结果/发现（必须带数值或明确方向）
- `limitation` — 局限/边界
- `condition` — 结论成立的前提条件

## 三、anchor 三段式

```json
{"page": 6, "section": "２ 检验结果分析", "quote": "２４ｈ预报的ＴＳ评分平均为０.４４"}
```

| 子字段 | 作用 | 粒度规则 |
|---|---|---|
| `page` | PDF 物理页码（1-based） | 必须有。印刷页码放顶层 `page_map` 映射 |
| `section` | 章节名，与 `section_outline` 里的 heading 一致 | 用于章节对齐；脚本会警告章节页不符 |
| `quote` | 原文逐字片段（20–60 字） | 正常页必须有；乱码/图片页允许空串 + uncertainty |

**为什么 page 用物理页码而不是论文印刷页码**：PDF 阅读器、平台渲染、页码定位全都按物理页序；印刷页码在不同版本里会变（期刊排版 vs 预印本），拿它当锚点会漂。用 `page_map` 做一层映射，两种页码都能回链。

## 四、status 判定

| result.status | 条件 |
|---|---|
| `ok` | 锚点核验无 weak / mismatch，任务项全 done |
| `partial` | 有 weak、mismatch、未完成任务项，或论文有异常页需人工核对 |
| `failed` | PDF 读不出 / 无法提取任何文本 |

**不得把 partial 写成 ok。** 评分看的是"未报告与不确定项是否被明确说明"，不是看 status 好不好看。
