# 阅读01｜文献文档解析 —— 准备与思路梳理

> 本文是开发前的准备文档：题面要求提取、公开 Skill 调研、突破方向选择、工作流设计与验证方案。
> 供参赛者审阅确认后，再进入深度开发与评估。

## 一、题面要求完整提取

### 1. 任务性质
制作一个**可被 Agent 调用的 Skill**，在组织方提供的 **3 个固定科研案例**上完成实际任务，交付可被复核的结果。3 个案例以相同内容分别交给「基础 Agent」与「加载参赛 Skill 的 Agent」，公平对照。**无需自带正式测试案例，无需提交预制答案。**

### 2. 题目提出的四个大问题（核心考察）
| 代号 | 问题 | 含义 |
|-|-|-|
| 提得全 | 能否逐字提取 | 正文、图表题注、脚注、参考文献不漏行、不丢段，页眉页脚不与正文混淆 |
| 排得对 | 阅读顺序是否正确 | 双栏/多栏/跨栏/跨页按原版面顺序输出，不串栏、不错行、不把相邻段落拼成一句 |
| 拆得清 | 结构还原是否清晰 | 章节层级、表格行列与单元格归属、公式上下标与希腊字母还原成可继续处理的结构 |
| 核得回 | 能否指回原文 | 每段文字、每张表能指回页码与区块；读不出的部分如实标注，不靠猜补齐 |

### 3. 可选择的突破方向（聚焦一种即可，不必做完整系统）
1. 多栏阅读顺序与文字提取（修正串栏、错行、漏段，处理页眉页脚、边注、跨页续接）
2. 复杂表格解析（跨行跨列、合并单元格、多层表头、跨页续表）
3. 章节与版式结构识别（标题/摘要/章节/段落/参考文献，多级层级与编号）
4. 公式与特殊字符（上下标、希腊字母、特殊符号，按公式编号对照原文）
5. 扫描版 PDF 与 OCR（图像预处理、识别、后处理校验）

### 4. 评分维度（满分 100 + GitHub 附加 5）
| 维度 | 分值 | 关键考察 |
|-|-|-|
| 实际效果 | 40 | 任务完成度 15、结果正确性 15、结果完整性 5、结果可核验性 5 |
| 使用增益 | 25 | 质量增益 15、效率增益 5、增益可验证性 5 |
| 创新增益 | 15 | 新增能力 5、方法改进 5、创新证据 5 |
| 可靠体验 | 10 | 调用易用性 3、运行稳定性 4、异常处理 3 |
| 生态贡献 | 10 | 文档完整性 3、资源可复用性 4、分享推广价值 3 |
| GitHub 链接 | +5 | 公开、无需登录可访问、能找到本次作品 |

### 5. 交付要求
- 只提交 **Skill 本体（SKILL.md）+ 必要资源 + 使用说明 + 最小示例**；
- 提交目录根路径放 `GITHUB_URL.txt`（第一行 GitHub 链接）；
- 每个案例输出结构化结果：**输入标识、主结果、证据/来源定位、运行状态、不确定性**。

### 6. Harbor 技术提交约定（运行时契约，以本题为准）
- 评测环境要求生成 `/app/submission/SKILL.md`（含合法 name/description YAML frontmatter）；
- 评测环境把 Skill 安装到 `/skills/weekly-skill`，用官方 DeepSeek Harness 跑固定案例；
- 运行时：原始输入 `/input/case.json` 与 `task.md`；工作目录 `/app/work`；结果 `/app/output/result.json`（含 case_id 与 output_contract 全部字段）；
- 预算：**64 次模型请求、900 秒、单响应 16384 token（含推理）**；
- Skill 资源：**≤50 个 UTF-8 文本文件，单文件 ≤500KB，总量 ≤2MB，禁符号链接**；
- 三案例、每条件三重复；失败单独暂停；诚实记录 partial、来源、不确定性、变更记录；不编造分数或科学数据。

## 二、公开 Skill 调研（可借鉴）

| 来源 | 定位 | 对我方案的启示 |
|-|-|-|
| Anthropic 官方 `pdf` skill | 本地 pypdf/pdfplumber/reportlab/qpdf 合并/拆分/抽取/填表 | 本地化、零云依赖；但非高精度版面引擎 |
| dptech-corp `bohrium-pdf-parser` | 调用 Bohrium Uni-Parser 云服务（0.05 元/页），提取文本/表格/公式/图表/分子/版面 | 官方定义了解析产物的**完整形态**（content + objects + pages_tree，含坐标、置信度、层级） |
| dptech-corp `UniParser-Tools` | UniParser 云服务 CLI，产出 pages_tree.json + Markdown，表格/公式 LaTeX/图/阅读顺序 | 明确了**版面树 + Markdown 双产物**、按 token 轮询、诚实核对等工程实践 |
| MinerU 类 skill | 高精度本地 PDF 转 Markdown（公式 LaTeX、表格、OCR） | 证明"本地也能做高精度版面解析"，可作为质量对标 |
| awesome-academic-skills 索引 | 222+ 学术 skill，含多套 PDF/OCR/阅读技能 | 说明学术 PDF 解析是高频刚需，竞争点在于**版面保真 + 可复核** |

**关键判断**：评测运行环境的 `resources` 只列了 `pdf-text-tool`（pdftotext）、`pdf-render-tool`（pdftoppm）、`ocr-tool`（tesseract）、`scientific-python`、`latex-compiler`、`office-renderer` 等**本地工具**，**没有** UniParser 云服务或付费 `bohr pdf`。因此本 Skill 必须**纯本地、零外联、零付费**，以 poppler（pdftohtml/pdftotext/pdftoppm）+ python3 为主，tesseract 兜底扫描件——这与我已搭建的 `extract_pdf.py` 架构一致。

## 三、突破方向选择（为拿高分）

**主攻：多栏阅读顺序与文字提取（排得对 + 提得全）**，理由：
1. 它是地基——题面明说"顺序对了，后续翻译、问答、知识提取才不读到拼接错的句子"；
2. 基础 Agent 用 naive `pdftotext` 最容易在这里翻车，**质量增益最直观、最可验证**；
3. 可建立**带 ground-truth 的阅读顺序测试集**，量化"正确率"（踩「结果正确性 15 分 + 增益可验证性 5 分 + 创新证据 5 分」）。

**次攻：复杂表格解析（拆得清）**，理由：
1. 表格是科研 PDF 里"实验参数与结果直接比对复用"的高价值元素；
2. 合并单元格/多层表头/跨页续表是基础 Agent 几乎不会处理的，是**新增能力**（踩「新增能力 5 分」）。

**其余三项（章节层级、公式保真、扫描 OCR）做扎实但非深挖**，保证四个问题都覆盖，踩「结果完整性 5 分 + 生态贡献」。

## 四、Skill 思路与流程（v2，在 v1 基础上增强）

```
/input/case.json + task.md
        │
        ▼
① 识别输入与问题边界（pdfinfo 页数/加密，pdffonts 文字层）
        │
        ▼
② 版面提取：pdftohtml -xml（文字+字号+字体+坐标，纯本地）
        │   └─ 无文字层 → pdftoppm + tesseract OCR 降级
        ▼
③ 版面分析：
   ├─ 分栏检测（正文行 x 直方图聚类，排除标题/页眉干扰）
   ├─ 阅读顺序重建（栏内按 y，栏间从左到右，跨页续接）
   ├─ 页眉/页脚分离（页边带 + 跨页重复）
   ├─ 章节层级（字号 + 加粗 + 编号模式，过滤目录点线行）
   ├─ 表格拆解（列 x 对齐网格 → 行×列单元格）
   ├─ 公式识别（数学字体 CMMI/CMSY + 特殊字符密度）
   └─ 图注/脚注/参考文献
        │
        ▼
④ 渲染页面核对：pdftoppm 出图，Agent 目视核对阅读顺序/表格/公式
        │
        ▼
⑤ 按题面答题：answer.<output_contract 字段> + evidence（页码/区块定位）
        │
        ▼
⑥ 写 /app/output/result.json（case_id + 全字段 + status + uncertainty + changes）
```

**相比 v1 的增强点（本轮开发要落实）**：
1. 阅读顺序重建改为**确定性栏排序 + 可选 Agent 目视校正**双轨，并输出 `reading_order` 可核验序列；
2. 表格解析支持**合并单元格/多层表头**（列边界对齐 + 跨行跨列推断）；
3. 增加 **ground-truth 自测脚本**，量化"阅读顺序正确率 / 表格结构还原度 / 章节命中率 / 公式保真率"四项指标；
4. 增加**异常用例**（扫描件、加密、无文字层、乱码）的识别与降级验证。

## 五、验证与评估方案

**验证语料（自建，用于本地评估，不冒充正式案例）**：
1. 双栏论文（如已下载的 Decision Transformer，NeurIPS 式双栏）；
2. 表格密集论文（含跨行跨列/多层表头）；
3. 公式密集论文（数学/物理类，验证上下标与希腊字母保真）；
4. 扫描版/低质量 PDF（验证 OCR 降级）。

**评估指标（在语料上量化）**：
- 阅读顺序正确率（对比人工标注的段落顺序）；
- 表格行列/单元格归属准确率；
- 章节层级命中率（标题/编号还原）；
- 公式符号保真率；
- 页眉页脚误入正文率。

**增益对照**：同输入下「基础 Agent（naive pdftotext）」vs「加载本 Skill」，对比上述指标——用真实数字证明「使用增益」，而非文字自述。
