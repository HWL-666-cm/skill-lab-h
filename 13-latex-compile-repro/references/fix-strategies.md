# 修复策略：哪些自动做，哪些必须交人工

## 判断标准

一个修复能自动化，当且仅当：**修复动作由日志唯一确定，且不改变作者想表达的科学内容**。

按这个标准，只有三类进自动路径：

### 1. 清理陈旧辅助文件

- 触发：`\abx@aux@refcontext` undefined、源码里没有的宏却报未定义。
- 动作：删 `.aux/.bbl/.bcf/.blg/.out/.toc/.lof/.lot`，从头全量重编。
- 为什么不直接改源码：这类错误来自上一次构建的残留状态，源码本身没问题，改源码是修错对象。

### 2. 切换 Unicode 引擎

- 触发：`Unicode character ... not set up`、CJK 字符在 pdflatex 下报 inputenc 错。
- 动作：从 pdflatex 切到 xelatex，重编；引擎选择写进 `build_manifest.json`。
- 为什么不自动删字符：那些字符是作者内容，删了就改变原意。

### 3. 补白名单内的标准宏包

- 触发：`File 'amsmath.sty' not found` 等，且包名在 `repair.py` 的 `SAFE_PACKAGES` 里。
- 动作：在 `\begin{document}` 前插入 `\usepackage{包名}`。
- 为什么限制白名单：第三方宏包可能有名字相近但行为不同的版本，猜错会引入更隐蔽的错误；白名单都是 CTAN 上的基础包。

## 必须交人工的类别

| 类别 | 为什么不能自动 |
|---|---|
| 表格列宽 / 数值 | 改列宽要权衡可读性，改数值就是篡改数据 |
| 公式符号与编号 | `\alpha` 与 `\beta` 的差别是科学含义，不是格式问题 |
| `\cite` / `\ref` 键 | 补哪个键取决于作者想引用哪篇文献/哪个公式，日志给不出答案 |
| 模板必填项 | 填什么内容属于作者决策；脚本只能指出缺哪一项 |
| 第三方宏包 / 字体 | 需要确认来源、许可证、版本兼容性 |

这些在 `changes.md` 里写成 `applied: false / needs_human: true`，附 `location`、候选方案和复验方法。**不写"已修复"**。

## 宽表的正确修法

社区共识（TeX Stack Exchange 多处一致）：**不要用 `\resizebox` 硬缩放**。原因：字号变小、线宽变粗、后续维护困难。

推荐顺序：

1. `tabularx` 的 `X` 列自动分配宽度；
2. `p{长度}` 定宽列，正文自动折行；
3. 减小 `\tabcolsep`（默认 6pt，可试 4pt）；
4. 整个表格统一 `\small` / `\footnotesize`，保持字号一致；
5. 确实跨页时用 `longtable`，而不是把表格压到一页。

避免用 `[H]` 强行固定浮动体位置，会导致后续内容大片空白；用 `\ref` 交叉引用让 TeX 自己决定位置。

## 修复循环何时停

`repair.py` 每轮：编译 → 诊断 → 应用安全修复 → 重编。停止条件：

- 编译通过且无阻断项；
- 或本轮没有任何新的自动修复被应用（继续循环只会空转）；
- 或达到 `--max-rounds`（默认 3）。

停在"仍有未解决问题"时，结果标 `partial`，问题进 `uncertainty`，不假装完成。
